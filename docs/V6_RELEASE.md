# V6 版本说明

> 当前产品版本：V6
> 更新日期：2026-07-15

## 定位

V6 在现有归档引擎上提供跨平台 Web 工作台。分析完成后先进入人工核对，在浏览器中按原 Word 表格版式修订五份系统表；Windows 可继续生成 DOCX，macOS / Linux 则将 HTML 系统表直接生成 PDF。两条路径最终都能进入归档合并流程。

## 当前功能

| 能力 | 实现 |
|---|---|
| 跨平台运行 | macOS / Linux 使用 HTML → PDF；Windows 可启用 DOCX/Word COM |
| 人工核对闸门 | 分析完成进入 `awaiting_review`，确认前不自动合并 |
| 原表浏览器编辑 | 档案卷宗、立案审批表、送达材料清单、结案报告表、质量监督卡采用声明式 HTML 表格 |
| 常见排版 | 可调整字体、字号、对齐；输入框边框不参与打印 |
| 补充信息 | 空白位置允许创建、移动、缩放和编辑文本框 |
| 长文本 | 单元格高度随内容增长，避免档案卷宗等长内容被截断 |
| 律所名称 | 立案审批表制表单位使用账号所属律所名称 |
| 送达材料 | 文件从序号 5 对应行开始逐份写入材料名称，每份占一个单元格 |
| 审办结果 | 同时综合诉讼与执行证据；存在执行材料时输出执行立案、措施、财产查控和终本/结案结果 |
| API 隔离 | LLM Key、模型地址、OCR Token 以 `user_id` 为边界独立保存 |

## 使用流程

1. 注册或登录，进入“我的 API 配置”填写本账号的 LLM 与 OCR 参数。
2. 新建案件并上传单卷 PDF，或上传多份已分类材料。
3. 启动分析，系统完成 OCR、文书切分、目录映射和字段提取。
4. 任务进入“待核对”，在五份原表版式中修订内容与格式。
5. 确认后生成系统表 PDF、计算目录页码并合并完整归档；后续修改可重新生成。

## 平台差异

### macOS / Linux

- 默认不生成 DOCX，不调用 Microsoft Word。
- 浏览器表格是主要编辑面；保存后由无头 Chrome/Chromium 输出 A4 PDF。
- 系统表 PDF 直接交给现有合并器，继续执行目录页码、排序与源页守恒校验。
- 可部署在本机或局域网服务器；需安装 Chrome/Chromium，或配置 `V5_CHROMIUM_PATH`。

### Windows

- 可设置 `V5_PREVIEW_ONLY=false` 启用 DOCX 生成与归档合并。
- Word COM 路径要求安装 Microsoft Word，后端保持单 worker。

环境变量继续使用 `V5_` 前缀以兼容已有 `.env` 和部署脚本。

## 数据边界

- `Case`、上传文件与输出文件按 `org_id` 隔离。
- API 配置按 `user_id` 查询和更新；同组织账号也不会共享密钥。
- 管理员旧全局配置只允许引导管理员自己的兼容数据，不向普通账号继承。

## 核心兼容层

Web 后端通过 `app/core/v4_bridge.py` 导入根目录中的成熟归档模块。文件名中的 `v4` 是历史兼容接口名；当前运行版本为 V6。为降低归档算法回归风险，本轮不进行大规模模块重命名。
