# 0619 开发计划 — AI 全自动 PDF 扫描归档

> **总目标**：达到「AI 根据 PDF 扫描文档**自动完成整个归档流程**」——
> 输入一份（或多份）扫描 PDF，输出**目录正确、文书归类正确、字段填写正确、零数据损坏**的完整归档 PDF + 系统表。
>
> **循环机制**：每轮（约 30 分钟）只做 **1 个最高影响问题**，跑 `loop_metrics` 验证不回退，
> 把结果与下一步写入本文件「迭代日志」。下一轮**只读本文件**最新计划继续，不依赖对话记忆。
> 上下文超限 → 清空 → 用文末「恢复语」继续。

## 一、成功判据（验收口径）

| 维度 | 指标 | 目标 |
|------|------|------|
| 数据完整 | `dup_pages`（重复纳入页） | **= 0**（硬约束，回退即失败） |
| 数据完整 | `gap_pages`（漏页） | **= 0**（硬约束） |
| 归类准确 | 法院文书/证据/保全各归正确 seq | 人工抽查命中率 ≥ 90% |
| 切分合理 | 无 >40 页的单一 complaint/execution 巨块吞并其他文书 | 巨块逐步拆出独立文书 |
| 字段填写 | 系统表关键字段「待确认」数 | 逐轮下降（依赖 LLM，单列追踪） |

## 二、量化工具

```bash
# 结构质量（快·确定·无 LLM/Word，走 OCR 缓存）— 每轮必跑
py scripts/loop_metrics.py
# 默认扫 test_sample/test_file/*.pdf（18 份）；可传指定 PDF

# 样本覆盖缺口分析（test_file vs standard_sample vs GT）
py scripts/analyze_sample_coverage.py

# 从 standard_sample 提取槽位级金标准目录（30/31 可解析）
py scripts/extract_standard_catalog.py

# 同名配对案件的槽位召回（当前仅 2019）
py scripts/compare_to_standard.py

# 回归（必须全绿）
py -m pytest tests/ -q
py scripts/verify_doc_order.py
```

评分公式（每案满分 100，越高越好）：
`100 - dup*5 - gap*3 - pdf_missing*8 - low_conf*1`；有 GT 时综合分 = 结构×0.4 + type_acc×100×0.6。

> **注意**：18 份 test_file 仅 3 份有逐页 GT，`loop_metrics` 输出的 avg 混合了无 GT 案的结构分，
> 须同时看 `gt_coverage` 与 `type_avg_gt_cases`（Iteration 8 后新增）。

> 注：`pdf_missing` **不参与结构扣分**（缺失目录项组装时跳过）；仅输出 `missing_pdf_seqs` 供参考。
> seq13 庭审笔录通常无卷；seq12 以「传票」(`summons`) 出现即算命中。

### Iteration 1 — 放宽 layout 闸门允许锚点切换【负结果·已回退】
- 改动：layout 存在时，页顶锚点指向「不同的明确文书类型」即允许切换（绕过 0.82 闸门）。
- 现象：units 增多（兴泰 3→4、容健华 7→8、2019 5→8），dup/gap 仍 0，结构 score 不变。
- **但 spans 类型正确性变差**（人工核对）：
  - 兴泰出现 `poa 21-51`（31 页 POA，荒谬——POA 必为 1 页）；
  - 2019 出现 `contract 27-67`（41 页）、且把原本干净的 `execution 68-98` 碎成
    `68-75 / contract 77-81 / 82-98`，执行段被插入伪合同。
- **根因**：切换后「无锚点页继承上一锚点类型」，短文书锚点（poa/invoice）会把后续
  几十页**继承成错误类型**；单纯多切换不解决「继承错类」。
- **结论**：回退。结构 metric（dup/gap/missing）**测不出类型正确性**，需引入 ground-truth。

### Iteration 2 — 建立 ground-truth 类型准确率基准【完成】
- `scripts/_dump_pages.py` 导出每页 OCR 标题；`scripts/ground_truth.py` 人工标注 3 案。
- `loop_metrics.py` 新增 `type_acc`（每页归属 seq 是否等于 GT），综合分=结构0.4+类型0.6。
- **关键纠错**：seq3「委托代理合同」是【律所委托/法律服务合同】；当事人之间的
  借款/授信/保证/担保/承兑/分期等业务合同是【提交法院的证据】→ seq7。初版 GT 误标，已改正。
- 真·基线（改正 GT 后）：兴泰 0.40 / 容健华 0.60 / 2019 0.414，avg **57.3**。
- 首要错误模式：业务合同+证据页(exp7)被 complaint(5) 巨块继承吞并。
- 附带验证：曾试「放宽闸门允许 contract 切换」反而把业务合同误判 contract(3)，对真 GT 是回退 → 已弃。

### Iteration 3 — 证据段识别 + 短文书回落 + 分段型闸门放行【完成·重大提升】
- 改动：
  1. `document_segmenter` 证据锚点新增「证据名称/证据来源」——证据清单常被 OCR 成无标题表格。
  2. `segment_by_catalog` 引入 `context_seq`（背景正文段）+ `prev_short`：短文书
     （授权书/发票/传票）只占本页，其后无锚点页回落到背景，不再吞并整段。
  3. layout 不完整时，**分段型**文书（合同/起诉状/证据/判决/裁定/执行/保全等）凭页顶锚点

### Iteration 4 — 字段「待确认」根因修复 + 模型切换【完成·重大提升】
- 改动：
  1. `config.json` 模型 `deepseek-v4-flash` → `deepseek-v4-pro`（用户提供 token，
     `/models` 确认两者均有效；pro 提取质量更高）。
  2. **根因 bug**：`field_merger._pick_value` 把 `"待确认"` 当作「已找到」直接返回，
     导致高优先级分路（如 judgment 对 `当事人`）输出占位符时盖掉低优先级分路（complaint/poa）
     的真实值。修复：新增 `_PLACEHOLDERS`/`_is_valid`，跳过占位符优先取有效值，
     全部无效时才回落占位符。
- 结果（兴泰，路径A 单卷）：`待确认` 字段 20→**13**（−35%）；
  委托人=广州银行佛山分行、承办律师=张鑫莹、对方当事人=兴泰贸易、
  审理法院=南海区法院、案由=金融借款合同纠纷 均正确填充；pytest 29 通过。
- 备注：`当事人` 仍为「原告/被告：待确认」——起诉状段 OCR 未明列当事人姓名，属切分/OCR 问题，
